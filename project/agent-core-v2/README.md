# Агент для безопасности браузера

Идея создания "живого" антивируса для поведения, а не просто для файлов или сигнатур — это сильный и своевременный замысел. Рынок перенасыщен блокировщиками рекламы и антивирусами, но инструментов, которые защищают пользователя от социальной инженерии и когнитивных ловушек в реальном времени, критически мало.
Реализовано через отслеживания действий пользователя в браузере playwright в реальном времени для оценки его безопасности в сети.


## - UserStories

### - - MVP1.0:
1) **Анализ в реальном времени**: 
    - пользователь заходит на страницу
    - *агент ищет информацию о сайте на который был совершен переход. И кеширует эту информацию. Вызывает функцию установления текущего уровня угрозы, в которую передает список причин выставления именно такого уровня угрозы из заданного в приложении списка*
    - пользователь видит в правом верхнем углу **маленький квадратный статус-виджет агента**. В котором отображен текущий уровень угозы для пользователя, который отображается цветом и ассоциативным изображением, понятным для пользователей с ограниченными возможностями.
2) **Предупреждение для предотвращения манипуляции**
    1. **Доброкачественный сценарий**
    - Клиент совершает действия в сети которые могут иметь непредвиденные последствия, например переходит в сбербанк онлайн после общения в мессенджере
    - *агент проверяет соответствие последовательности действий с заданными сценариями. И находит соответствие -> Вызывается шаблонное уведомление*
    - Клиент видит крупное уведомление. Например: "Внимение! Будте внимательны переводя деньги по просьбе в мессенджере. Это может быть стандартной мошеннической схемой. Пожалуйста, будьте аккуратны!."
    ``` Сообщение не должно быть навязчивым, данный контекст является самым спорным. Гарантируется большое количество ложных срабатываний. Так как в целях безопасности данные на конфиденциальных страницах  не будут обрабатываться внешним агентом. Вместо этого сервис должен выступать как "наставник" информационной безопасности. Ненавязчиво постоянно напоминая пользователю что нужно проверять новые номера прежде чем перевести на них деньги по просьбе в мессенджере, ведь это самая частая мошенническая схема. Анализ будет производится по ключевым словам вроде "код", "секретный код" и последовательности действий в сети мессенджер -> банк. Если постоянное срабатываение будет выделено навязчиво , то у пользователя появится привыкание и следственно он будет игнорировать агента. Или , в худшем случае навязчивое уведомление оттолкнет пользователя от пользования приложением. Поэтому уведомления такого плана должны быть визуально привлекательными, приятными, интересными , но при этом отображать суть, а самое главное ассоциироваться с предосторожностью. Для этого будет использоваться анимированный маскот```
    2. **!Ложные срабатывания**
    - Пользователь общается с женой в WhatsApp и заходит в Сбер перевести ей деньги за продукты. Агент выдает плашку "Осторожно, мошенники!". Три таких срабатывания — и пользователь навсегда отключает агента или игнорирует красный цвет. **!!Нужен очень тонкий анализ тональности!!**

### - - MVP1.1:

3) **Анализ страницы по запросу**:
    1. Продвинутый пользователь(разработчик)
    - Пользователь хочет проверить сайт (возможно свой) на соответствие нормам и спецификациям. Или уточнить возможный уровень доверия к сайту. 
    - пользователь нажимает на **статус-виджет агента**. В открывшемся меню нажимает кнопку **"проанализировать страницу"**
    - **Агент проверяет страницу и сайт на соответствие официальным требованиям, выявляет нарушения из перечня, находит владельца сайта данные о нем в перечне (регистрация в ркн и whois для примера), определяет уровень доверия к странице.**
    - в отдельном окне пользователь видит перечень выявленых несоответствий и найденую в открытых источниках информацию о странице и сайте
    ```
    Этот userstory является нишевым. Но надо понимать что агент УЖЕ будет выполнять все эти действия "под капотом". Но для обычного пользователя они не нужны. Ведь цель приложения - оградить его от таких тонких подробностей и технических деталей. Но по опыту разработки очень часто необходимо в "один клик" найти всю информацию на сайте. потому что обычно для этого приходится посещать ряд несвязанных источников. И это реальный проверенный кейс. (Например реестр актуальных требований ркн, whois, и т.д). Иметь полный анализ по всем этим источникм нажатием одной кнопки - очень полезный инструмент, который экономит время разработчика , и помогает избежать ошибок "по невнимательности". Кроме того всей этой информацией, как говорилось ранее УЖЕ оперирует сервис, так что с точки зрения разработки для реализации этой UserStory необходимо только вывести готовые данные
    ```
    2. Обычный пользователь
    - Пользователь сомневается в надежности платформы, на которой он находится. Возможно, его предостерег **статус-виджет агента** о возможной опасности. 
    - пользователь нажимает на **статус-виджет агента**. В открывшемся меню нажимает опцию **"причины опасности"**. 
    - *Интерфейс берет из хранилища данные списка причин , которые были переданы агентом и отображает их*
    - пользователь видит в открывшемся окне список причин по которым выставлен текущий уровень опасности и иконку загрузки ответа - подробного разъяснения ии агента.
    - *Посылается "долгий" запрос к агенту, с передачей текущего контекста, действий клиента и списка причин для получения простого для понимания пользователя объяснения опасности его действий с предостережением*


### - - V1.0:
Перечисленый функционал требует максимального быстродействия, для таких действий как: **анализ DOM дерева по шаблонам** и разделения браузерной части от аналитического процесса, кроме того , для обеспечения лояльности пользователя и сайтов и систем, анализирующих работу браузера нужно отойти от идеи отдельного экземпляра браузера. При этом весь основной функционал приложения должен быть доступен даже при проблемах с доступом к удаленным ресурсам (серверам). Поэтому для реализации V1.0 Было принято решение , используя MVP реализацию как архитектурный шаблон перенести проект на стек REACT + Tauri Что отвечает самым последним требованиям разработки.
